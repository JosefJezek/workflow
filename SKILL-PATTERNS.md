# Deterministic AI Skill Patterns

| # | Pattern Name | Target Core Focus | How It Achieves Determinism (Mechanism) | Real-World Production Example |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Structured Outputs** | Data Formatting | Constraints the LLM's token generation engine using strict JSON schemas or Pydantic models. Syntactically invalid text is physically impossible to output. | Extracting user data from an email directly into a fixed `{ "name": string, "age": int }` database object. |
| **2** | **Tool Calling (Function Calling)** | System Actions | The LLM acts purely as an intelligent router. It extracts parameters from natural language and maps them to hardcoded backend subroutines. | "Book a room for tomorrow at 6 PM" -> AI yields `{ "date": "2026-07-12", "time": "18:00" }` to a legacy reservation API. |
| **3** | **Code Generation Pattern** | Computational Logic | The probabilistic LLM generates deterministic code (SQL, Python, Bash) *once*. Traditional software then executes this code mechanically with 100% predictability. | AI writes an optimized PostgreSQL query based on a user's question; the backend runs it safely via an ORM. |
| **4** | **Skillflows (Micro-Skills)** | Complex Processes | Breaks massive, monolithic prompts into sequential, single-purpose, and fully isolated execution steps (Chains) with explicit data contracts. | A loan approval pipeline: Step 1 validates ID format -> Step 2 fetches credit score -> Step 3 runs calculations. |
| **5** | **Self-Validating Skill Harness** | Skill Autonomy | Wraps atomized capabilities into TypeScript classes (like `BaseSkill`) that enforce strict input/output type contracts, loop budgets, and checkpointing locally. | Creating an invoice parser that internally manages its own token spending, input validation, and file persistence without relying on global state. |
| **6** | **Human-in-the-Loop (HITL)** | Safety & Compliance | Separates the generative ideation phase from the executive action phase. AI drafts the solution, but a human must manually click "Approve". | An AI medical assistant drafts a patient prescription, but the system blocks transmission until a licensed doctor signs off. |
| **7** | **Guardrails (AI Firewalls)** | Content Security | Surrounds the LLM with independent input/output validation layers (regex, toxicity classifiers) that intercept and block non-compliant content. | An outbound filter intercepts an AI response containing leaked PII (GDPR violation) and replaces it with a generic safe fallback message. |
| **8** | **Retrieval-Augmented Generation (RAG)** | Knowledge Grounding | Forbids the model from answering using its internal weights. Injects verified static documents into the prompt context via keyword or vector search. | A corporate HR bot answering questions *strictly* based on the uploaded PDF handbook, eliminating hallucinations. |
| **9** | **Self-Correction Loop** | Output Quality | Runs the AI's output through a strict compiler, linter, or parser in a closed program loop. If it fails, the error log is fed back to the AI for a retry. | AI generates a Python script -> Python compiler returns a `SyntaxError` -> AI reads the error, fixes the code, and re-runs it successfully. |
| **10** | **Intent Routing** | Traffic Gateway | A fast, tiny classifier triage system evaluates user inputs at the gateway. Simple or highly sensitive requests completely bypass the generative AI. | User inputs "Delete my account" -> Router immediately short-circuits the LLM and triggers a traditional, hardcoded account deletion script. |
| **11** | **Input Triage & Grill-with-Docs** | Quality & Verification | Confronts user bug reports directly against internal docs and logs. Rejects incomplete tickets or handles configuration errors autonomously. | User claims endpoint `POST /export` is broken. AI finds they missed the required `X-User-Role` header in docs, rejects the ticket, and instructs user to fix it. |
| **12** | **Finite State Machine (FSM)** | Execution Flow | Strips the AI of any control over the application's state transitions. Transitions are governed entirely by hardcoded rules in a "Deterministic Shell". | In an e-commerce bot, the system transitions from 'Cart' to 'Checkout' *only* when traditional code verifies the items are still in stock. |
| **13** | **Checkpointer (Persistence)** | Fault Tolerance | Atomically serializes and saves the agent's full state (history, variables) to a database after every single step. Protects against crashes. | A server restarts mid-execution due to a power surge; the revived agent reads `state.json` and resumes exactly from Step 3 instead of resetting. |
| **14** | **Supervisor & Sub-Agents** | Hierarchy & Scaling | A master supervisor coordinates tasks by treating specialized sub-agents as black-box tools. Sub-agents cannot talk to each other and escalate errors upward. | A customer support Supervisor delegates a billing question to a Billing Agent, who returns a clean answer without knowing the main thread context. |
| **15** | **Anti-Rationalization Skills** | Behavioral Discipline | Utilizes formalized Markdown playbooks (`SKILL.md`) with explicit execution tables to intercept and block AI excuses, laziness, or shortcut attempts. | An agent tries to skip writing unit tests by stating "I'll do it later"; the anti-rationalization guardrail detects the phrase, halts execution, and forces `npm test`. |
| **16** | **Self-Reflection / Learning Skill** | Permanent Evolution | Catches execution failures, tasks an LLM to extract a generalized "lesson learned", and appends it to a global permanent JSON memory for future runs. | A code bot learns that a specific API endpoint has changed, writes a rule to `global_memory.json`, and never calls the old endpoint again. |
| **17** | **Constitution & Living Spec** | Context Engineering | Forces the AI to write and validate comprehensive Markdown specifications (`spec.md`, `plan.md`) based on a project 'Constitution' *before* writing code. | Popularized by GitHub's SpecKit; prevents "vibe coding" by binding the AI code generation to rigid, pre-approved architectural boundaries. |
| **18** | **Visual Regression & Verification** | Multimodal Validation | Uses a headless browser (Playwright) to capture screenshots/videos of generated UI. Compares pixels and layouts using Vision LLMs to audit design and animations. | During code refactoring, a mathematical pixel-diff engine guarantees the user interface appearance hasn't shifted by even a single pixel. |
| **19** | **Ephemeral Sandbox** | Execution Security | AI-generated code is executed exclusively inside a short-lived, isolated container (e.g., Docker or Micro-VM). The environment is destroyed instantly after execution. | Running untrusted, AI-written Python automation scripts without risking host system corruption, data leaks, or infinite loops. |
| **20** | **Dual-Model Judge (Critic)** | Objective Evaluation | Tasks a separate, typically larger or highly specialized model to audit the outputs of a faster "actor" model based on specific verification criteria. | A fast 8B model generates a customer service email draft; a powerful 70B model reviews it for professional tone and correctness before approval. |
| **21** | **Language Agent Tree Search (LATS)** | Complex Planning | Employs tree-search algorithms (like Monte Carlo) over LLM thoughts. Generates multiple paths, evaluates probabilities, and backtracks if a route fails. | Autonomously planning a complex multi-stop business trip flight path by exploring, scoring, and discarding non-optimal booking combinations. |
| **22** | **Shadow Mode (Silent Pilot)** | Risk-Free Deployment | Deploys a new AI agent to production silently. The agent processes real incoming traffic parallel to humans/legacy systems, but its outputs are never sent to users. | Testing an automated trading or customer support bot for 30 days to measure semantic alignment with human choices before going live. |
| **23** | **Ensemble Voting** | Statistical Accuracy | Sends the exact same prompt to multiple independent models (or one model sampled multiple times) and uses a democratic voting mechanism to pick the final response. | Preventing rare mathematical hallucinations by checking if 4 out of 5 models agree on the exact same numerical result. |
| **24** | **Blackboard Pattern** | Shared-State Memory | Multiple independent, uncoordinated specialist agents work on a single centralized data structure (the blackboard). They only act when the state matches their skill. | A complex multi-agent coding framework where a Linter Agent, Test Agent, and Doc Agent all read from and update a single `project_state.json` file. |
| **25** | **Model Cascade (LLM Tiers)** | Cost & Latency Control | Routes the input to the cheapest, fastest model first. If a deterministic verification metric (or small LLM confidence score) fails, it scales to a larger model. | A classification task hits an ultra-fast local 1B model. If confidence is $<0.9$, the request automatically escalates to a cloud-hosted 405B frontier model. |
| **26** | **Semantic Compaction (Context Triage)** | Memory Optimization | Instead of passing infinite chat logs, a background process deterministically truncates, compresses, and highlights raw text into a condensed, lossless vector summary. | Keeping a multi-month customer chat session active by programmatically replacing old raw conversations with a compact, bulleted entity graph. |
| **27** | **Generative Simulator (What-If)** | Blast-Radius Containment | Forces the AI to generate a synthetic simulation of the environment it is about to affect, allowing it to "pre-test" the impacts of destructive actions. | Before an AI execution agent drops or alters a live database column, it creates a mock-schema simulation to verify that 0 downstream APIs will break. |
| 28 | Token Circuit Breaker | Financial & Loop Safety | Monitors prompt/completion token usage and monetary cost in real-time. Automatically cuts off API access (trips the breaker) if a threshold is breached. | Preventing a runaway autonomous looping agent from burning through a $500 corporate API budget in a single night due to an unhandled exception. |
| 29 | Deterministic Shell (Hybrid Nodes) | Efficiency & Guardrails | Strips pure business logic, calculations, and math out of the LLM prompt. Forces the AI to act only as a semantic parser, executing steps via raw code. | Instead of asking an LLM to calculate a 21% VAT invoice sum from text, the AI parses the raw price via JSON (Pattern 1) and standard code computes the exact math. |
| 30 | Isolated Eval Harness | CI/CD Regression Testing | Runs a single isolated skill dozens of times against a static golden dataset before deployment to benchmark its cost variance, accuracy, and latency. | Preventing an unexpected model weights update from causing a production invoice skill to hallucinate currency conversions. |

## 📚 Verified Sources, Frameworks, and Communities

### 📁 GitHub Repositories (Pattern Catalogs)

* [zeljkoavramovic / agentic-design-patterns](https://github.com/zeljkoavramovic/agentic-design-patterns): A comprehensive visual and text catalog containing 29 core agentic patterns split into Orchestration, Reliability, Memory, and Control.
* [ai-boost / awesome-harness-engineering](https://github.com/ai-boost/awesome-harness-engineering): A curated list focused on strict software wrappers (harnesses) built around probabilistic models to force deterministic behavior.
* [FareedKhan-dev / all-agentic-architectures](https://github.com/FareedKhan-dev/all-agentic-architectures): A technical repository mapping over 30 advanced planner and search architectures including Tree of Thoughts and LATS.
* [evoiz / Agentic-Design-Patterns](https://github.com/evoiz/Agentic-Design-Patterns): Production-ready Jupyter notebooks with live Python code showcasing ReAct, Structured Outputs, and Multi-Agent workflows.
* github / spec-driven-development: Core reference documentation for Spec-Driven Development (the foundation of the Project Constitution pattern).
* [addyosmani / agent-skills](https://github.com/addyosmani/agent-skills): Google engineer's reference repository for creating highly formalized, anti-rationalization executable Markdown workflows (SKILL.md) for advanced agents.
* [rpamis / comet](https://github.com/rpamis/comet): Production agent skill harness for evaluation, prompt regression testing, and CI/CD validation loops.

### 🛠️ Recommended Production Frameworks

* LangChain / LangGraph: The industry standard library for compiling agents as strict Finite State Machines (FSMs). Built-in support for checkpoints, state persistence, and hierarchical supervisor orchestration.
* Pydantic / PydanticAI: A type-safe Python framework designed explicitly to enforce structured data input/output contracts and safe execution layers around LLMs.
* mastra-ai / mastra: A TypeScript-first backend framework engineered specifically for building lightweight, scalable workflows, tools, and vector synchronization without Python dependencies.

### 💬 Active Engineering Communities (Reddit)

* [r/AI_Agents](https://www.reddit.com/r/AI_Agents/): Main architecture hub for discussing multi-agent systems, context isolation, and containing agent blast-radius.
* [r/LLMDevs](https://www.reddit.com/r/LLMDevs/): Backend-focused forum dedicated to LLM reliability, token circuit breakers, middleware layers, and cost minimization.
* [r/vibecoding](https://www.reddit.com/r/vibecoding/): A community focused on modern AI development tools, advocating for Spec-Driven approaches to prevent agents from writing unstructured code based on pure "vibes".
